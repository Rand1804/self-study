# Claude Code 功能速查手册

> 用途：使用 Claude Code 时忘记某个功能、入口或适用场景时快速查询。已省略安装、启动和基础对话内容。

## 功能入口速查

| 想做什么 | 用什么 |
| --- | --- |
| 查看全部可用命令 | `/help` |
| 初始化或更新项目记忆 | `/init` |
| 切换新任务，清空上下文 | `/clear` |
| 长会话压缩上下文 | `/compact` |
| 查看或切换模型 | `/model` |
| 查看账号、模型、额度、环境状态 | `/status` |
| 调整配置 | `/config` |
| 管理文件和命令权限 | `/permissions` |
| 管理 MCP 服务 | `/mcp` |
| 管理子 Agent | `/agents` |
| 管理插件 | `/plugin` |

## 上下文管理

| 场景 | 操作 |
| --- | --- |
| 当前任务结束，准备做新任务 | `/clear` |
| 对话很长但任务还没完成 | `/compact` |
| Claude 开始引用旧信息 | `/clear` 后重新给必要背景 |
| 只希望它看部分代码 | 明确文件或目录范围 |
| 不想让它猜未读文件 | 明确要求“只基于已读取内容判断” |

常用提示词：

```text
只阅读 src/auth 和 tests/auth，先总结你看到的事实，再给修改计划。
```

```text
请只基于当前文件和测试结果判断，不要假设未读过的模块。
```

```text
先不要改代码，先告诉我你需要读取哪些文件以及原因。
```

## 文件与输入方式

| 输入类型 | 用法 |
| --- | --- |
| 本地文件 | 直接给路径，例如 `src/api/user.ts` |
| 目录范围 | 直接给目录，例如 `src/auth`、`tests/auth` |
| 图片 | 用于 UI、报错截图、流程图、设计稿 |
| 多行文本 | 用于日志、配置、接口返回、需求说明 |

常用提示词：

```text
请阅读这个文件，提取所有可疑逻辑，不要修改：src/api/user.ts
```

```text
下面是错误日志，请分析根因，只给出需要检查的文件和最小修复方向：

...日志...
```

## Git 工作流

| 场景 | 提示词 |
| --- | --- |
| 查看当前改动风险 | `请 review 当前 git diff，优先找 bug、回归风险和缺失测试。` |
| 修改前规划 | `先阅读相关代码，给出最小修改计划，不要直接改。` |
| 修改后验证 | `运行相关测试，检查 git diff，总结改动。` |
| 生成提交信息 | `根据当前 diff 生成一条清晰的 commit message。` |
| 提交前检查 | `检查当前 diff，运行必要测试，指出是否可以提交。` |

推荐流程：

```text
先看 git status 和 git diff，区分我的已有改动和你需要改的内容，不要覆盖无关改动。
```

## Claude.md 项目记忆

`Claude.md` 适合保存项目长期规则，不适合保存一次性需求。

适合写入：

- 项目启动方式。
- 测试、lint、格式化命令。
- 代码风格。
- 禁止修改的文件或目录。
- 提交、PR、review 规范。
- 项目目录说明。

示例：

```markdown
# Claude 项目规则

- 修改前先说明计划。
- 保持改动最小，不做无关重构。
- 测试命令：npm test。
- 检查命令：npm run lint。
- 不要修改生成文件，除非任务明确要求。
```

常用提示词：

```text
根据这个项目的启动方式、测试命令和代码规范，更新 Claude.md。
```

## Auto Memory

Auto Memory 用来沉淀个人偏好或长期规则。

适合保存：

- 沟通偏好。
- 常用测试命令。
- 固定开发规范。
- 反复出现的项目约束。

不适合保存：

- 临时需求。
- 临时调试结论。
- 密钥、Token、账号信息。

常用提示词：

```text
把“以后修改前先给计划，保持改动最小”记为长期偏好。
```

## Skill 技能扩展

Skill 是可复用的专项工作流。

适合做成 Skill：

- 代码审查。
- 测试生成。
- 文档整理。
- API 使用规范。
- 前端 UI 检查。
- 固定格式的报告生成。

不适合做 Skill：

- 只做一次的任务。
- 还不稳定、经常变化的流程。
- 单句提示就能说明白的简单要求。

常用提示词：

```text
把这个代码审查流程整理成一个 Skill：先检查 bug，再检查测试缺口，最后给风险摘要。
```

## MCP 扩展

MCP 用来把外部工具、数据源或服务接入 Claude Code。

常见用途：

- 访问数据库。
- 查询内部文档。
- 调用浏览器或设计工具。
- 接入 API、日志平台、搜索服务。
- 连接文件系统、项目管理或自动化工具。

入口：

```text
/mcp
```

使用建议：

- 只接入高频、明确有用的 MCP。
- 工具过多时，让 Claude 先说明准备调用哪个工具。
- 涉及写操作、删除操作、发布操作时要求先确认。

常用提示词：

```text
查看当前 MCP 列表，说明每个 MCP 能做什么，以及我什么时候该用。
```

```text
先不要调用 MCP，先说明你准备调用哪个工具、读取什么信息。
```

## CLI 命令行工具

CLI 能让 Claude Code 执行项目命令。

常见用途：

- 跑测试：`npm test`、`pytest`、`cargo test`、`go test ./...`
- 跑检查：`npm run lint`
- 查看状态：`git status`、`git diff`
- 启动服务：`npm run dev`

常用提示词：

```text
先说明要运行的命令和原因，再执行。失败后只定位直接相关原因。
```

```text
运行最小相关测试，不要跑全量测试，除非必要。
```

## 子 Agent

子 Agent 适合把复杂任务拆给不同角色处理。

适合使用：

- 大型项目规划。
- 多模块并行分析。
- 代码审查和实现分离。
- 一个 Agent 查问题，一个 Agent 看测试，一个 Agent 整理方案。

不适合使用：

- 单文件小修。
- 明确简单的 bug。
- 不需要并行分析的任务。

入口：

```text
/agents
```

常用提示词：

```text
为这个大型重构拆分子 Agent：一个分析调用链，一个检查测试覆盖，一个制定最小改动方案。
```

## Hook 钩子

Hook 用来在特定时机自动触发动作。

高频场景：

- 提交前运行格式化检查。
- 提交前运行测试。
- 修改文件后做安全提醒。
- 生成提交信息前检查 diff。
- 执行高风险命令前提醒确认。

文档推荐示例：

```text
设置一个 hook，每次提交代码之前，都会自动触发代码格式的检查。
```

使用建议：

- Hook 只放稳定、快速、必要的动作。
- 不要把耗时很长的全量测试挂到每次操作。
- 安全类、提交前检查类 Hook 最实用。

## Plugin 插件

插件是打包了 Skill、SubAgent、Hook、MCP 的整合能力。

入口：

```text
/plugin
```

插件管理中可以：

- 收录和下载插件。
- 查看已安装插件。
- 管理插件能力。

文档推荐插件：

| 插件 | 功能 |
| --- | --- |
| `commit-commands` | 简化 Git 工作流，包括提交、推送、创建 PR。 |
| `content-creator` | 生成博客、视频脚本、社交媒体内容等。 |
| `security-guidance` | 编辑文件时提示命令注入、XSS、不安全代码模式等风险。 |

使用建议：

- 先装少量高频插件。
- 插件能覆盖稳定流程时再启用。
- 不清楚用途的插件不要长期启用。

## 常用任务提示词

### 代码审查

```text
请 review 当前 git diff，优先找 bug、回归风险和缺失测试。按严重程度输出，给出文件和行号。
```

### 修 Bug

```text
先复现或定位问题，再给最小修改方案。不要做无关重构，修完运行相关测试。
```

### 新功能

```text
先阅读项目结构和相关模块，列出要改的文件、原因和验证方式。等我确认后再实现。
```

### 重构

```text
保持行为不变，只重构指定范围。先说明风险点，改完运行现有测试。
```

### 写测试

```text
为这个逻辑补充最小必要测试，覆盖正常路径和关键异常路径，不改业务逻辑。
```

### 生成提交信息

```text
根据当前 diff 写 commit message，第一行用祈使句，正文说明主要改动和验证情况。
```

### 总结项目

```text
阅读项目入口、README 和主要目录，输出项目结构、启动方式、测试命令和关键模块。
```

## 使用原则速记

- 新任务：`/clear`。
- 长任务：`/compact`。
- 查工具：`/help`。
- 查状态：`/status`。
- 查 MCP：`/mcp`。
- 查插件：`/plugin`。
- 长期规则：写入 `Claude.md`。
- 重复流程：做成 Skill。
- 外部工具：接入 MCP。
- 自动检查：设置 Hook。
- 组合能力：安装 Plugin。
